---
The goal is to have a set of printers connected in various states.
Then we want to have an endpoint that we can submit parts to, with some
requested print deadline.
The system should then allocate parts to builds and make sure that
each build is printed by the time required for each part in the build.  So 
the system will hold back parts as long as possible to allocate them into
efficient builds, and there will be some logic showing when we want to 
send the build to be printed (either when it is full, or when we need
to print it to meet part deadlines)

We then want to be able to scrub through time and see status of everything.
That might mean calling a status endpoint with a datetime, or scrubbing 
through in the UI, or it might be showing expected part allocations on
a graph, and a Gantt showing expected print job times.

---
The current design intent is to query the graph through GraphQL 
but to POST parts for printing via extensive business logic in
a regular FastAPI endpoint.  Partly to have the distinction as a 
discussion point, because we could obviously add logic in a 
GraphQL mutation.

Similarly, to have concrete examples to discuss, I intend to have
two front ends - one handwritten, one generated automatically 
but specified through openspec.
